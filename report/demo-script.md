# GlossX Demo Day 演示脚本（草稿）

按 8 分钟准备，课程给出的时长确定后再增删。每段写了“讲什么”和“屏幕上做什么”。演示前一天按文末清单把数据准备好，现场不依赖网络搜索。

## 0. 开场（0:00–0:45）

- 讲：研究者在阅读器、文献管理、聊天机器人、编程 agent 之间来回切换；通用 agent 写得流畅但引用经常对不上原文（ScholarQABench 上 GPT-4o 有 78–90% 的引用是编的）。
- 讲：GlossX = 我们开源的论文阅读器 Gloss，升级成面向科研与学习的 agent harness。一个小内核，其余都是插件。
- 屏幕：README 封面图 → 打开 GlossX 桌面端。

## 1. 架构一页（0:45–1:30）

- 屏幕：报告 Fig. 1 架构图。
- 讲：内核只有四个模块、约 1,260 行（能力注册表、权限与预算闸门、运行管理与 trace、loop 驱动）。工具、skill、MCP、Claude Code / Codex、SSH 都通过 6 种适配器变成同一种 Capability。
- 讲：核心 agent 的五步 route → plan → execute → verify → reflect；agent 之间传的是证据片段 ID，不传全文。

## 2. 主演示：团队综述（1:30–4:00）

- 屏幕：选中文库里 3–4 篇结论互相冲突的论文，输入问题（例：“这几篇对 X 的结论是否一致？”），不手动选工作流。
- 指出：路由自动选中 `team-review`，状态栏能看到计划的步骤图。
- 指出：每篇论文一个 reader 并行在读；critic 找出冲突，把问题发回对应 reader；反驳轮。
- 指出：最终答案里每句话都带引用，点一下引用跳到 PDF 原文并高亮。
- 指出：验证器拒掉的 claim 单独列在 rejected 里，不进答案、不进项目记忆。

## 3. 第二个工作流：辅导 + 学习者模型（4:00–5:15）

- 屏幕：课程讲义 PDF 或 PPT，问“给我讲讲 X，然后出题考我”。
- 指出：先读学习者档案，已掌握的概念一句带过；答完题掌握度更新，下一次讲解深浅会变。

## 4. 安全与鲁棒性（5:15–6:00）

- 屏幕：带提示词注入页的 PDF，问一个普通问题，展示 agent 没有照注入指令做。
- 屏幕（可选）：让 reproduction 工作流调用 Codex，展示运行前的审批弹窗。

## 5. 评测结果（6:00–7:30）

- 屏幕：报告 Table 2、Table 3（真实数字出来后替换）。
- 讲：同一底座模型下对比 Gloss 原版对话、Codex、pi；引用能否在原文定位、虚构引用率、支持率；去掉验证器 / 反思的消融。
- 讲：可扩展性——最新加的 team-review 工作流是 35 行清单 + 86 行插件代码，内核改动 0 行。

## 6. 收尾（7:30–8:00）

- 讲：开源、桌面端 + 手机端、评测框架和 Route-100 一起发布。下一步：更多基准（PaperArena 等）、自进化 skill。
